1 · Executive summary

Autogram discovers laws from data by letting an LLM propose a grammar (a bounded vocabulary of candidate relations) from variable names only, then exhaustively enumerating every candidate law in that grammar, screening each with the Z3 solver, and keeping only the laws the values support. It was built for and tuned on CrossCheck: wide tables where every row is an independent network snapshot and the laws are per-snapshot algebra (equalities, family sums, conservation, bounds).

gtib is a different kind of dataset. It is long/tidy, scalar-celled telemetry of a byte-completeness SLO, and its high-value laws are temporal and dynamic: ratios, rolling-window ratios, cumulative monotonicity, per-consumer proportionality, and relations that hold only under a categorical condition. Those shapes are the ones the CrossCheck family list does not cover, so most of them are not expressible in Autogram today.

The plan is five phases, each independently shippable and testable:

  • Ingest
    read long/tidy CSV → wide observations
  • Ratios
    division identity + learned proportionality
  • Time
    lag, difference/rate, rolling window
  • Conditionals
    relations conditioned on a label
  • Advanced
    cross-grain joins · multi-term logic
Scope: build all five phases — we optimize for the most complete, highest-quality discovery, not for minimal effort. Phases 0–3 cover every observable gtib data law; Phase 4 adds the relational-join, multi-term-conjunction, and run-length machinery so even the alert-defining rules become discoverable. The one law no method can recover from this data is A1 (byte conservation), because its latent backlog term is never emitted — a property of the data, not of Autogram.

The rule shape (DSL)

Every candidate is a single quantified atom:

∀ b in <binder>:  L(b)  <op>  R(b)

The engine grounds it to a residual population ρ = L − R with scale s = max(|L|,|R|), then asks: on what fraction of points is |ρ| ≤ tolerance·s? A law is accepted if that hold-rate clears a threshold with a Wilson confidence interval, and if Z3 says it is non-trivial.

What it can express today

  • Terms: Ref (a column), Const, Scale (fixed coeffs −1, 0.5, 2), Add (n-ary sum), Agg (SUM/MIN/MAX/AVG over a family), Mul, Div (behind degree ≥ 2).
  • Ops: ~= (within band), ==, <=, >=, !=, <|> (presence pairing).
  • Capability tiers widen the grammar on demand: tier 1 turns on all aggregations, tier 2 turns on products/ratios (max_degree = 2).
The load-bearing constraint: a rule relates columns within a single row (one binding). There is no notion of time, order, lag, or "the previous row". Every gtib law that references time is therefore out of reach until Phase 2.

4 · The four core gaps to close

Gap 1

Shape & granularity of the data

Autogram expects a wide table (columns = variables, rows = independent observations). gtib is long/tidy: identity lives in row values (consumer_id, shard_id, minute_index), and it comes at two granularities (one row per shard per 10 s of raw counters, and one row per consumer per minute of derived quantities). Ingestion — reading the files into Autogram's internal table — must reshape to wide observations and, for the one cross-granularity law, pre-compute the per-minute shard increments.

Gap 2

No time axis

Rules relate columns within one row. gtib's signature laws are across rows in time order: monotonicity (Δx ≥ 0), rolling-window ratios, and lagged slopes. The DSL needs new temporal terms (lag, difference/rate, rolling window) and a grounding path that works per ordered group instead of per independent row.

Gap 3

Ratios & learned constants

The completeness ratio is a literal CR = OR/IR per-row division identity, and metering is a proportionality OR ≈ η·IR with a per-consumer constant η. Division exists in the DSL (degree 2) but is not scorable as a known invariant, and there is no way to fit an arbitrary coefficient (scale coeffs are the fixed set {−1, 0.5, 2}). Fitting that constant from data is exactly a symbolic-regression sub-problem; Phase 1 borrows a robust estimator for it.

Gap 4

Conditional relations

Several laws hold only on a subpopulation: counters rise unless a reset; loss stays flat on benign spans and grows on true-loss spans. The DSL is a single unconditional atom, so it needs an optional condition (where label == …) that filters the residual population before the hold-rate is computed.

5 · The phased plan

Phase 0

Ingest gtib as wide observations

scope: data-prep + CLI

Goal. Get gtib's derived table into Autogram so each per-(consumer, minute) row is one observation and the quantities (completeness_ratio, output_rate…, backlog_bytes, …) are Ref leaves under one binder. This is mostly data prep, not engine change: the "scalar" cell codec already exists, and induction already reads flat column names.

Design.

  • 0a — per-grain wide frame. Write a tiny converter that loads timeseries_derived.csv and emits a pickled DataFrame with one row per (consumer, minute) and scalar columns.   • 0b — cross-grain materialization (for B7/B3). Also emit per-minute shard-increment columns shard_<k>_input_increment so a family SUM can be tested (input_rate == SUM(shard_*_input_increment)). This is the pragmatic way to reach the one cross-grain sum without an engine change.
  • Accept a .csv path directly in the CLI so the converter can be skipped later.

Phase 1

Ratios & learned proportionality as scorable shapes

scope: new operator + scoring

Goal. Make the ratio identity CR = OR/IR (B1) and the metering proportionality OR ≈ η·IR (C1) declarable, enumerable, screened, accepted, and scored against a known-invariants file.

Design.

  • B1 is already enumerable once max_degree = 2 (the Div node exists). The gap is that a ratio is not a recognised known-invariant shape, so it can never be scored. Add a {ratio: [num, den]} rhs form.
  • C1 needs a coefficient fit from data. Add a proportional-equality operator ~∝: for y ~∝ x, fit the constant with a robust estimator borrowed from symbolic regression — the Theil–Sen estimator or RANSAC (Fischler & Bolles, 1981), which shrug off the burst/overshoot outliers, falling back to least squares — then score the hold-rate of |y − ĉ·x| ≤ tol·s. Fitting a small number of real coefficients from a candidate term is precisely what symbolic-regression systems do (e.g. sparse regression, PySR-style search), so adopting their estimators keeps the step principled; the constant is fit from data like the band, never hard-coded, so the "data decides" contract holds.

Phase 2

A time axis, grounded in established theory

scope: core temporal grounding

Goal. Give the DSL a first-class time axis so it can relate a value to earlier values in the same ordered group (a consumer, or a consumer + shard). We adopt conventional notation and established theory rather than inventing bespoke terms.

Two standard frameworks supply everything:

  • The backshift (lag) operator from classical time-series analysis (Box & Jenkins, 1970): B shifts one step, so Bᵏx = x[t−k], and the first-difference operator is ∇ = 1 − B (thus ∇x = x[t] − x[t−1], a rate). A rolling window is a finite sum of lagged terms. These are the algebraic terms — standard operators, not new inventions.
  • Signal Temporal Logic (STL) (Maler & Nickovic, FORMATS 2004) for the temporal predicates, with bounded operators □[0,W] ("always within a window") and ◇[0,W] ("eventually"). STL's quantitative robustness semantics (Fainekos & Pappas 2009; Donzé & Maler 2010) return a real-valued margin, which maps directly onto Autogram's residual/band — Autogram's monitor already is a robustness evaluator, so STL is the natural home for these laws.

The new terms are then standard operators, and the laws are STL formulas over them:

# AST nodes implement the backshift algebra:  Bᵏ (lag),  ∇ (difference),  Σ_window (rolling sum)
monotonicity     □(∇x ≥ 0)                                  # A3 / A4
windowed ratio   x  ~=  (Σ[0,60] OR) / (Σ[0,60] IR)          # B2
lagged slope     (x − Bᵏx) ≤ 0                              # B5 slope term

A complementary lens for the rate laws is sparse identification of nonlinear dynamics (SINDy; Brunton, Proctor & Kutz, PNAS 2016): it fits governing equations of ∇x by selecting from a library of candidate terms — exactly Autogram's enumerate-then-select loop applied to differences. It is the reference point for the difference/rate templates and confirms the approach is standard practice.

Phase 4

Cross-grain joins & multi-term logic

scope: relational + logic layer

Goal. Complete the picture — the cross-granularity sum, multi-term conjunctions, and run-length predicates — so even the alert-defining rules become discoverable, not just the simple data laws.

  • B3 (cross-granularity rate). Build a first-class relational join between the per-shard-step and per-consumer-minute granularities (a binder that aggregates the finer grain into the coarser), so IR = Σshards ∇(counter) is discovered directly. The Phase-0b materialization is the fast path; the join is the general one, and we build both.
  • B4 (sustained alert). Add a run-length operator, i.e. the STL bounded-always □[0,10min] (Maler & Nickovic), so "below threshold for ≥ 10 consecutive minutes" is a first-class predicate with quantitative robustness.
  • B5 (full trajectory rule) & B6 (oracle). Add a conjunction node (∧ of atoms) so multi-term alert definitions are expressible; oracle_alert == is_true_loss is then a plain boolean equality, and the label-from-spans mapping a categorical relation.
  • A1 (byte conservation with the latent backlog term) is the one law no method can recover from this data, because the physical input/output counters it needs are never emitted. That is a data limitation, not an Autogram one.

A single known_invariants.yaml drives calibration and recall scoring. Below is the target file; each entry is annotated with the phase that makes it declarable. Entries in green work today; the rest depend on the new declaration forms this plan adds.

Inputs & references. The dataset is data/gtib-emulation/timeseries_derived.csv (raw counters in timeseries_raw.csv); the full invariant catalogue with the A/B/C IDs used here lives in data/README.md; the executable ground-truth contract is generator/gtib_emulator/invariants.py; and the declaration syntax mirrors docs/known_invariants.example.yaml, parsed by autogram/discovery/known.py.

invariants:
  # ── Phase 0 · works today ─────────────────────────────
  - {name: backlog_non_negative,      op: ">=", lhs: backlog_bytes,             rhs: 0}
  - {name: input_rate_non_negative,   op: ">=", lhs: input_rate_bytes_per_min,  rhs: 0}
  - {name: output_rate_non_negative,  op: ">=", lhs: output_rate_bytes_per_min, rhs: 0}

  # ── Phase 1 · ratio + proportionality (new rhs / op) ──
  - name: completeness_ratio_definition
    op: "=="
    lhs: completeness_ratio
    rhs: { ratio: [output_rate_bytes_per_min, input_rate_bytes_per_min] }
  - name: metering_proportionality
    op: "~∝"
    lhs: output_rate_bytes_per_min
    rhs: input_rate_bytes_per_min

  # ── Phase 2 · temporal (new term forms) ───────────────
  - name: cumulative_loss_monotone
    op: ">="
    lhs: { delta: cum_lost_bytes }          # value[t] − value[t−1]
    rhs: 0
  - name: smoothed_ratio_windowed
    op: "=="
    lhs: completeness_ratio_1h
    rhs: { ratio: [ {roll_sum: [output_rate_bytes_per_min, 60]},
                    {roll_sum: [input_rate_bytes_per_min, 60]} ] }

  # ── Phase 3 · conditional (new 'where' clause) ────────
  - name: true_loss_accumulates
    where: { label: true_loss }
    op: ">"
    lhs: { delta: cum_lost_bytes }
    rhs: 0
  - name: benign_spans_lose_no_bytes
    where: { label_in: [benign_burst, artifact] }
    op: "~="
    lhs: { delta: cum_lost_bytes }
    rhs: 0
The ratio, ~∝, delta, roll_sum, and where forms are new declaration syntax introduced by Phases 1–3. Each must be taught to known.py:_signature (parse) and validate.py:_operand_sig (match) — they are coupled and must be changed together.

7 · Calibration recipe for gtib

Commands

# 0. sanity: can the harness induce a schema?
autogram precheck --harness copilot

# 1. reshape long → wide (Phase 0 converter)
python scripts/gtib_to_wide.py \
  data/gtib-emulation/timeseries_derived.csv \
  --out gtib_derived_wide.pkl

# 2. calibrate against the known file
autogram calibrate \
  --input gtib_derived_wide.pkl \
  --known gtib_known.yaml \
  --band-mode adaptive \
  --max-capability-tiers 3 \
  --out gtib_report.json

Why these knobs

  • adaptive band: gtib laws span very different scales (byte counters vs. a ratio near 1), so a per-candidate capped band fits better than one global tolerance.
  • max-capability-tiers 3: reaches products/ratios (needed for B1/B2). Phase 2 adds a further temporal tier beyond these three.
  • proxy suite is derived from the calibration-split shapes; the new shapes (ratio, proportional, temporal, conditional) each need a planted proxy in synth.py so they can be tuned generically, never against the real gtib answers.
  • null control stays on: read false_discovery.null_equalities_accepted in the report — it must stay at 0. Recall is only meaningful next to it.
  • read the contract first: docs/calibration_protocol.md and AGENTS.md define the loop and the calibration/validation split; per-dataset configs live in configs/ (mirror configs/abilene.yaml); learned rules are written to rules/.

9 · Risks & scope

Core change, fully isolated

Phase 2's grouped-temporal grounding changes the core assumption that residual points are independent rows, touching dsl/evaluate.py and its interaction with subsampling, the band split, and support counting. It lands behind a capability flag, leaving the per-row path byte-for-byte intact — and the CrossCheck golden test proves it, so existing learning is never disturbed.

Enumeration blow-up

Temporal terms multiply the candidate space (each ref × each lag × each window). Bound them hard: a tiny allowed window set (e.g. {45, 60}), max_lag small, and temporal terms gated to their own capability tier so they only appear when simpler tiers stall.

Solver completeness

Ratios and temporal terms are Z3-opaque (like Div today), so logical pruning weakens and more candidates reach the statistical gate. Acceptable, but expect larger portfolios; lean on the archive's subsumption and the null control.

Non-regression guarantee. Every new capability (ratios, temporal operators, conditions, cross-grain joins) is added behind a capability flag or a new tier, and the default per-row path is unchanged. A checked-in golden test re-runs the Abilene and GÉANT discovery after every phase and fails the build if the accepted portfolio or recall shifts at all — so extending Autogram for gtib provably cannot degrade what already works on CrossCheck.

The one thing no method can recover here

A1 byte conservation (I = O + Q + L) — its physical counters are never emitted, so no discovery method can observe it

Any brand-new relation shape must flow through six functional stages. This is the checklist to consult for every new op/term the plan introduces (file → function).

(a) Let the LLM propose it · (b) Enumerate it
  • (a) Propose — discovery/induce.py → _schema_prompt (the only place the model learns the contract: ops, agg kinds, degree, role conventions) + the _augment_* helpers. No change if the shape uses existing roles/ops.
  • (b) Enumerate — dsl/ast.py (new Term node or OPS/AGG_KINDS entry) · discovery/propose.py → _candidate_rules (a term builder + a yield block) · dsl/typecheck.py → is_admissible (relax so the form passes) · dsl/grammar.py (new caps such as max_lag/windows).
(c) Screen it in Z3 · (d) Accept it statistically
  • (c) Screen — logic/solver.py: _term_expr (Z3 encoding, opaque fresh real if not exactly encodable) · atom_expr (new op) · _leaf_key/_leaves (recognise new leaves).
  • (d) Accept — dsl/evaluate.py → eval_term (vectorised evaluation) · evaluator/band.py → violation_magnitude (if a new coverage form) · discovery/evaluate.py → evaluate (a branch computing holds, a tolerance knob) · discovery/archive.py → _op_strength (ranking + don't get dropped by the scaled-slack filters).
(e) Declare it as known · (f) Match/score it (recall)
  • (e) Declare — discovery/known.py → _signature (parse the new {op, lhs, rhs}) + shapes_for_invariant (map to a proxy shape id) + docs/known_invariants.example.yaml.
  • (f) Score — discovery/validate.py → _operand_sig (emit a relation signature) + a Recovery field + score_recovery line · discovery/synth.py (plant the shape in make_synthetic + _planted; ensure the null never plants it) · discovery/regime.py → KNOWN_SHAPES.

Coupling to remember: declaration (known.py:_signature) and matching (validate.py:_operand_sig) recognise the same structural forms — a new shape must be added to both or it can be declared but never scored (or vice-versa).
